# Orcaの通常欄・伏せ字・明示表示の比較

2026-11-14。チェックポイント `a8e44b219156a54836661f6e3d620b26ebdb6af4` のcommit / Gitea push後、[実機での初回報告](dev5-physical-orca.md)を切り分けた。**日本語・英語とも私有環境の28チェックが成功した。** 製品コード・上流・通常環境の設定・導入パッケージは変更していない。

## 方法

既存の `tests/ui_orca.py` を拡張した。私有GNOME / Wayland / D-Bus / XDGディレクトリで実際のOrcaを起動し、`tests/private_keyboard.py` が検証する専用コンポジターへだけキーを送る。通常ログインの仮想入力・unsafe-mode・全アプリ音声ログは使わない。入力は全て公開してよい合成文字列。

各キー入力でフォーカスとロールを確認し、実入力後の文字数3を検査する。通常欄ではq・z・v全ての発話を陽性対照とする。伏せ字欄ではAT-SPIが返す文字のマスクと、Orcaが3キーを保護対象として処理した記録を確認する。単にログに文字が無いだけでは合格としない。

明示表示は、Shift+F10で開いたGTKの文脈メニューを実Orcaの読み上げと矢印キーでたどり、「テキストを表示」を操作する。メニューの操作後に同じ合成値の公開状態を検査し、再び伏せ字へ戻す。これは製品への試験用フックではなく、通常のGTK機能の操作。

## 結果

| 条件 | 実入力・AT-SPI | 実Orca |
| --- | --- | --- |
| DB名（通常欄） | 3文字入力、textロール、qzvを取得 | q・z・v全てを読む |
| マスター欄・伏せ字 | 3文字入力、password text、文字はマスク | 英字を読まない。3キーの保護判定を記録 |
| 確認欄・伏せ字 | 同上 | 同上 |
| マスター欄・明示表示 | 同じ合成値を取得。**ロールはpassword textのまま** | 表示切替後にqzvを読む |
| マスター欄・再伏せ字 | 同じ値が再びマスク | 内容の発話なし |
| 再伏せ字で再入力 | 新たな3キーを入力、マスク | 英字を読まない |
| エントリーのパスワード欄 | 3キーを入力、マスク | 英字を読まない |

**ロールだけでは伏せ字の判定に足りない。** 明示表示時もpassword textを維持しつつ、取得内容・発話は変わる。GtkPasswordEntryが表示切替を提供することは [固定版GTK 4.22.4の実装](https://github.com/GNOME/gtk/blob/4.22.4/gtk/gtkpasswordentry.c#L145)とも一致する。一般的なキーエコーの説明は [Orca公式](https://help.gnome.org/orca/preferences_key_echo.html) を参照。実行版の結果はウェブ上の最新版の説明とは分けて評価した。

実行版は既存のGTK 4.22.4、libadwaita 1.9.1、Orca 50.3。日本語は `build/ui-orca-modes-ja8/`、英語は `build/ui-orca-modes-en/`。各フォルダーの `echo-cases.json` に条件・ロール・文字数・マスク・合成値の発話有無を記録し、`result.log` は28チェック。私有の `orca-debug.log` は合成データだけで、秘密を含む全文ログを実機から集めたものではない。

## 初回報告の扱い

通常欄・明示表示ならqzvが読まれる条件を確認したが、実機の初回がどの条件だったかは特定できない。利用者の記憶が無い部分を推測して埋めず、**初回は原因不明の観測のまま**。今回の条件比較で伏せ字の保護漏れは再現しなかった。初回を誤操作と断定したり、製品を修正して解決したと表示したりしない。

現在の比較で新しい製品パッチは必要と判断していない。伏せ字が確認できる条件で再発した場合は、配布・実データ利用への影響を優先評価し、合成入力で条件を記録して修正・回帰試験を行う。公開資料では経緯と制限を保持する。

## 試験基盤の停止と修正

`ja`〜`ja7`は完走していない。GIの同名メソッド解決、UTF-8ログのbyte / 文字位置、GTKのpopoverをroot treeから取得する方法、私有ポインターAPI、明示表示でロールも変わるという誤った試験前提を調整した。いずれも試験コードの問題として記録し、製品・依存の修正は行っていない。

ポインター試験の追加は撤回し、`tests/private_keyboard.py` はチェックポイントと同一。最終版は既存の私有キーボードとOrcaのメニュー発話を使う。表示切替後にpasswordロールが維持されることを許容し、文字のマスク状態も検査する。初期停止のログは `build/ui-orca-modes-ja*/` と `.cache/orca-modes-ja*.log` に保持した。

再現：`KPXC_UI_ORCA_ROOT="$PWD/build/任意の新規保存先" bash tools/test-ui.sh --orca`。英語は `KPXC_UI_LANGUAGE=en` を加える。Orcaが無い環境では導入前に相談し、試験を黙ってスキップしない。
