# 読み込みと KDF の資源制限

更新日：2026-11-12。対象：KeePassXC `1c2f23ef5914c0f442a00533def1689857afb5a7`。

## 今回の実装

**確認済み。** アプリの解除経路に、鍵導出前の KDF 検査、宣言長を Qt に渡す前の検査、復号・展開量の制限を追加した。暗号・KDF・KDBX の処理は引き続き上流を利用する。今回の検査は `src/gnome/ReadBudget.h:1`、既定値は `prototype/ReadLimits.h:9` にある。上流への追加変更が必要な理由を報告した後、`patches/0003-read-resource-policy.patch:1` として実装した。参照チェックアウトは変更しない。

`CoreSession::unlock` はファイルを一度開き、通常ファイルかを調べ、上限付きで暗号化バイト列を読み取る。FIFO の open で待たないよう `O_NONBLOCK` を指定する。事前ヘッダー検査と鍵付き読み込みは、同じ読み取り専用メモリバッファを使う。事前検査の後でパスを開き直す経路は廃止した（`prototype/CoreSession.cpp:149`）。

シンボリックリンクは、開いた対象が通常ファイルなら許可する。通常ファイルの I/O 待ち時間を保証する方式ではない。読み取り中の元ファイルの変更を完全に検出する機能や、ファイルシステムの原子的なスナップショットを作る機能も追加していない。ただし、取得後の検査と復号が異なる入力バイト列を使うことはない。

上流の読み込み中に有効なスコープを設け、各パーサーが同じ制限と診断を参照する。スコープは呼び出し元スレッドに限定し、終了時に復元する。KDF は上流が別スレッドで実行するため、その開始前に元のヘッダーの型・値を検査する。上流 API を直接呼ぶ参照 CLI・上流テストには、アプリのスコープを設定しない。システム全体の Qt / GTK 設定は変更しない。

候補モデルは全ての読み取りと終端検証に成功してから公開する。失敗時は破棄し、画面の一覧、パスワード取得、保存には渡さない。ファイルを直接開く上流の `Database::open` から、メモリデバイスを読む既存 `KeePass2Reader` へ接続を変更した。ファイル監視は開始せず、読み込み完了後に clean 状態へ戻す。元ファイルへの上書きは引き続き提供しない。

## 開発版の暫定上限

これは KDBX 仕様の上限ではない。正当な大規模 DB や重い KDF 設定でも拒否する場合がある。通常環境への自動調整や、画面からの上限解除は設けていない。

| 対象 | 上限 |
| --- | ---: |
| 暗号化された入力ファイル | 128 MiB |
| 外側ヘッダー合計 / フィールド数 | 1 MiB / 64件 |
| 外側の1フィールド | 1 MiB |
| 1辞書の項目数 / 名前 | 64件 / 1 KiB |
| 辞書内の1値 | 1 MiB以下、かつ残りの入力以下 |
| 内側ヘッダー合計 / フィールド数 | 64 MiB / 4096件 |
| 内側の1フィールド | 16 MiB |
| HMAC / ハッシュの1データブロック | 16 MiB |
| 復号・展開して供給するバイト数 | 256 MiB |
| AES-KDF の反復 | 100,000,000回 |
| Argon2 のメモリ設定 | 256 MiB |
| Argon2 の反復 / 並列度 | 20回 / 8 |
| Argon2 のメモリ設定 KiB × 反復 | 1,048,576 KiB以下 |

根拠は `prototype/ReadLimits.h:9` と `src/gnome/ReadBudget.h:108`。範囲外の設定を小さい値へ丸めて読み込むことはしない。試験用 API では上限を下げられるが、開発版の既定値より大きくする指定や0は拒否する。

外側ヘッダーの長さ・件数・合計と元入力の残量を検査してからフィールドを読む。辞書の名前と値は、それぞれローカルバッファの残量も確認する。重複した辞書キー、辞書終端の欠落、終端後の残りも拒否する。内側フィールドとブロックは、大きな読み込みを要求する前に宣言長を確認する。

圧縮時は `QtIOCompressor` の出力、非圧縮時は暗号ストリームの出力を数える。後者は KDBX 3.1 の開始バイトとハッシュのフレーミングも含む。入れ子の添付の展開がある場合は、その出力も同じ予算を使う。上限に達しても、出力のない正常な終端処理は許可する。超過検出用に最大1バイトの追加出力を処理するが、超過分をモデルに渡さない。

このバイト数は **プロセス全体の最大 RAM 使用量ではない**。モデルのオブジェクト、文字列、XML、ライブラリ、暗号化スナップショット等は別にメモリを使う。上記の積も計算時間の厳密な見積りやタイムアウトではない。

## KDF の型と互換性

上流が整数を `int` 等へ変換する前に元の値を調べる。AES の反復は正の値で `int` に表現可能なものだけを許可する。KDBX 3.1 の64ビット反復も、切り詰める前に検査する。

KDBX 4 の辞書では、UUID と salt は ByteArray、AES の反復は UInt64、Argon2 の版と並列度は UInt32、メモリと反復は UInt64 を要求する。文字列等の自動変換、メモリの KiB 単位への丸めは許可しない。既知の形式へ変換する際に捨てられる追加キー、Argon2 の `K` / `A` も拒否する（`src/gnome/ReadBudget.h:170`）。

**互換性上の制限。** このビルドの Botan 経路で正しく処理できる Argon2 1.3（`0x13`）だけを許可する。Argon2 1.0（`0x10`）を1.3として計算する問題への暫定対応は、鍵導出前の拒否である。1.0 の正しい読み書きを実装したという意味ではない。これらの設定を持つ正当な DB にも、専用の日本語・英語メッセージを返す。

上限超過、未対応・保持不能の KDF、ローカル通常ファイルを読めない場合は、通常の解除失敗と区別して GTK に返す（`src/main.cpp:371`、`po/ja.po:1`）。パスワードの誤りと一般の破損の区別は行わない。ファイルの内容や秘密を診断メッセージへ埋め込まない。

## 検証

**確認済み。** `gnome_reader_resource_tests` の196ケースが成功した。`tests/reader_finalization.cpp:6` から、既存の上流ベースの合成生成器を共用し、`--policy` で実行する。

- KDBX 3.1 / 4.0 / 4.1、圧縮あり・なしで、ファイル・外側ヘッダー・フィールド・ブロック・展開出力等の上限ちょうどを許可し、超過を拒否した。
- 辞書と内側ヘッダーの各上限、短い入力に対する巨大宣言長、辞書の重複・欠落・末尾を検査した。
- KDBX 3.1 / 4 の AES の0・過大反復・整数の桁落ち、Argon2 の版・型・メモリ・反復・並列度・積、追加キーを鍵導出前に拒否した。Argon2d / Argon2id 1.3 の小さい正常対照も認証・復号できた。
- 疎な過大ファイルと、書き手のいない私有 FIFO を処理せずに拒否した。FIFO への待ち状態は生じなかった。
- 拒否時に候補モデルを公開せず、一覧・秘密の取得・保存が使えないこと、スコープが残らないことを検査した。

`ReadStats::kdfStarts` は上流の `setKey` を開始する直前の到達回数である。認証前に拒否するケースでは0回、正常な解除では1回になることを確認した。ブロック・展開量等の認証後の制限は、鍵導出1回の後に拒否する。暗号プリミティブ全ての呼び出しを計測する指標ではない。

悪意ある宣言長を含む試験には、試験プロセスだけのアドレス空間1 GiB・CPU 10秒の制限と CTest 30秒のタイムアウトを置いた。ガードが退行したときに検証環境で巨大な割り当てを許すための試験にはしない。これらのプロセス制限は製品アプリにはまだ導入していない。

既存352ケースの終端検証、無変更の上流 CLI との互換性、選択した上流 Qt Test 群と言語試験も通過し、CTest 合計11項目が成功した。ログは `.cache/reader-resource-policy.log`、`.cache/ctest.log`、`build/Testing/Temporary/LastTest.log`。実データは使用していない。

## その後の進展と未解決事項

XML・モデルの予算と保持不能データの拒否は、2026-11-13 に [追加実装・検証](xml-model-preservation.md) した。以下は、この資源検査を追加した時点で残っていた事項である。

1. XML の深さ、グループ・エントリー・履歴・参照・添付等のオブジェクト数。一部の参照はパーサーが仮のオブジェクトを作るため、タグ数だけでは足りない。
2. 未知の XML、外側・内側の追加フィールドやフラグなどを失わずに扱える条件。今回の KDF 辞書の拒否だけで、DB 全体の保持を保証しない。
3. CPU / RAM / 時間のプロセス単位の制限、ロック時の中断、同時処理、I/O 待ち。暗号化メモリスナップショットとモデルの合計を含む最大使用量の測定。
4. Argon2 1.0 の正しい対応と、独立した実装による KDF の相互運用。
5. 保存・復旧・外部更新検出、画面ロック・スリープ、秘密のメモリ寿命、Wayland のクリップボード失効。

GUI の新しい拒否メッセージをネイティブファイル選択から表示する経路、明暗変更等の実環境試験と、VM へのインストールは別途必要。今回の成果で実データ利用や公開の合格とはしない。
