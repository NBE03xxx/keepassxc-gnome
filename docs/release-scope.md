# 公開対象と受入範囲

利用者は、日常的な短時間の個人利用、Ubuntu 26.04を対象として公開する方針を指定した。従来の主要環境GNOME 50 / Waylandで検証する。他のOS・デスクトップの対応を今回の受入条件には加えない。

## 利用と検証の範囲

- 短時間は、試験上は1回5〜30分程度を目安にする。この時間は利用者指定の厳密な上限ではなく、検証のための作業上の定義であり、超過時にアプリを強制終了しない。
- 個人用DBの作成・解除・編集・検索・コピー・保存・ロックを確認する。データ保持、理由付きの入力拒否、安全保存・復旧、秘密情報の扱いの基準は維持する。
- 数日間の常駐、他のOS・デスクトップ、大規模DBの性能保証は今回の公開時の対応範囲に含めない。現在の読み込み上限は明示する。
- スコープを定めても、既存試験の失敗を成功へ変更しない。60分反復で残ったメモリ増加は既知の事実として保持する。

## 公開候補を作るまで

1. 整理後にも残るメモリ増加の割り当て元と保持・解放の性質を調べ、観測事実・推論・未検証を区別して記録する。
2. 最新版のソース・依存・バイナリを固定して開発版debを作る。対応ソースとチェックサムを保持する。
3. Ubuntu 26.04 VMで導入・更新・配置・合成データ操作・キャッシュ整理をまたぐ表示と入力を確認する。
4. VMを通過した同じdebを実機で確認する。実機の認証、音声聴取など利用者の操作が必要な場面は案内する。既存の本家KeePassXCや本番DBは変更・使用しない。
5. 残件と対象範囲をREADME・利用手順に反映し、完成度に応じた公開時の位置付けを最終判断する。

現在は検証中である。今回の公開方針の指定だけでGitHubへのpush・リポジトリ作成は行わない。公開操作はAGENTS.mdの明示指示の規則に従う。

メモリの直近の結果は [キャッシュ制御](font-cache-control.md)、配布の基本手順は [配布・保守](distribution-maintenance.md)、過去の実機結果は [実機検証](physical-final-check.md)。最新版の確認と過去の結果を区別して記録する。

## 候補で明示するメモリの制限

検証中のlibadwaita 1.9.1-0ubuntu0.2には、ダイアログ等のレイアウト制御に使うbreakpointの解放漏れがある。ダイアログを作る回数に応じて保持量が増える。上流の修正を確認したが、この候補はシステムのライブラリを置き換えない。アプリ終了でプロセスのメモリは回収される。認証・編集ダイアログ本体の解放と入力消去は検査済みである。

この既知問題と、周期的に増減する描画キャッシュを [保持の性質の調査](gui-retention-characterization.md) に区別して記録した。長時間・大量の反復での総保持量上限は未検証で、既存の長時間試験の未合格は維持する。短時間の個人利用向けの候補としてVM→実機で検証し、公開の最終判断にこの制限を含める。
