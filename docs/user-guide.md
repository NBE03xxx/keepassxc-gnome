# 利用・バックアップ・復旧の手順

対象：KeePassXC GNOME v0.2.0、Ubuntu 26.04 / GNOME 50 / Wayland。日常的な短時間の個人利用を対象とする。大切なDBはバックアップを確保し、本家や同期アプリとの同時編集を避ける。対応範囲と既知の制限を本書に記載する。

## 導入・更新・削除

本アプリは本家KeePassXCと別のパッケージ・アプリIDを使用する。配布されたdebと同じ版の対応ソース、manifest、SHA256SUMSを一組で保存する。署名が提供される公開版では、公開鍵の出典と署名を確認してから使用する。checksum一致だけを発行者の署名確認とは扱わない。

ダウンロード先で `sha256sum --check SHA256SUMS` を実行し、導入前に `apt-get --simulate install ./対象.deb` で変更を確認する。想定外の削除・置換があれば実行せず、計画を確認する。実導入は管理者の認証を伴う `sudo apt install ./対象.deb`。更新も新しいdebを同じ方法で指定する。公開パッケージ名は `keepassxc-gnome`。旧開発パッケージ `keepassxc-gnome-development` がある場合は、それだけを置き換える。本家KeePassXCは置き換えず、既存の設定・履歴・復旧の保存場所は維持する。

削除は `sudo apt purge keepassxc-gnome`。利用者のDB・復旧記録はパッケージ削除で消さない。依存の自動削除は本手順に含めない。公開・実機導入の前にVMで確認する開発手順は [配布・保守](distribution-maintenance.md)。

初回は「KeePassXC GNOMEへようこそ」と中央の「データベースを作成」「データベースを開く」を表示する。最後に正常に開いた／関連保存した1件だけを履歴にし、次回は「ロックを解除してください」とファイル名を案内する。固定の既定DBではなく、別のDBを開けば置き換わる。中央の解除ボタンからパスワードを入力し、Enterまたは「ロック解除」で開く。起動だけではDBを読み込まず、パスワードも保存しない。メニューの「最近のデータベースを履歴から削除」で案内を消せる。DB本体は消さない。解除中はヘッダーにファイル名を表示する。

KDBXの右クリックの「別のアプリで開く」から、本家KeePassXCと本アプリを選べる。明示済みの既定アプリをインストールで上書きしない。既定を変更する場合はファイルのプロパティから利用者自身が選ぶ。既定が未設定の環境ではOSが候補を自動選択する場合がある。詳しくは[歓迎・履歴・関連付け](welcome-recent-file-associations.md)。

## 対応する入力

KDBX 3.1 / 4.0 / 4.1の既知データを上流KeePassXCのreader / writerで扱う。既存DBはパスワード、キーファイル単独、または両方で解除できる。型・設定・資源上限・保持検査に通らない入力は理由付きで拒否する。YubiKey、Argon2 1.0、任意の未知構造は対応範囲外。

本家KeePassXCで作成したキーファイルをそのまま選択できる。キーファイル単独のDBでは解除画面の「マスターパスワードを使用する」をオフにする。両方を設定したDBではオンのまま、同じパスワードを入力してキーファイルを選ぶ。選択は毎回行う。キーファイルは16 MiBまでのローカルの通常ファイルに対応する。新規DBのキーファイル設定や鍵の変更は本家KeePassXCで行う。

GTKに編集画面がない履歴・添付・TOTP・連携用属性等も、対応する既知データは保持する。ただし保持と機能の実装は別で、Browser・Auto-Type・SSH Agent・Secret Service・Passkey等の連携を提供するという意味ではない。詳細は [互換性方針](compatibility-policy.md) と [保持試験](known-data-compatibility.md)。

ファイル128 MiB、展開256 MiB、XML深さ128等の製品側上限がある。大きいDB、重いKDF、応答の大きい検索・属性は、形式として正しくても処理できない場合がある。保存・初期復旧保護にも資源が必要で、解除だけで判定しない。上限一覧は [読込方針](read-resource-policy.md)、[XML・モデル](xml-model-preservation.md)、[プロセス制限](reader-process-limits.md)。

拒否された場合は原本を保持する。拒否理由、アプリ・上流・依存の版を報告し、実際のパスワード・秘密・本番DBを添付しない。未対応の入力を、このアプリで無理に再保存しない。

## 編集・保存・コピー

左のグループを開いて選ぶと右上にそのグループ直下のエントリーが表示される。エントリーの単一クリックは右下のプレビュー、ダブルクリック・Enter・編集アイコンは編集画面を開く。上下の高さは境界をドラッグして変えられる。アイコンはグループの鉛筆ボタン「グループを編集」とエントリー編集画面から標準69種類を選べる。グループでは名前とアイコンを一緒に変更し、グループ編集の保存後にDB全体も保存する。詳しい保持と保存の違いは[グループ編集と互換性](group-icon-editing.md)を参照する。既存カスタム画像は保持するが、現在の表示は汎用画像アイコンとなる。選択行の背景はアクセント20%の固定混色で表示する。

1. DBを作成するか、既存DBを選んで設定済みのパスワードやキーファイルで解除する。初期の暗号化復旧コピーを確保できるまで、解除完了とは表示しない。
2. グループ・エントリーを作成・編集する。編集画面の「エントリーを保存」でモデルへの変更を確定する。この時点で編集の復旧コピーを保護するが、元のDBファイルへ保存済みとは限らない。
3. DB全体の「保存」で元のDBへ保存する。「新しいファイルに保存」は保存先を切り替える。「別名コピーを保存」は独立したコピーを作り、編集中DBの保存先・未保存状態を変えない。
4. 未保存中はヘッダーの「未保存」、ファイル名の「•」、色の付いた保存ボタンが目印になる。終了時の確認から「保存（上書き）」を選ぶこともできる。新規DB等では「名前を付けて保存…」で保存先を選ぶ。保存が成功してから閉じ、取消・失敗なら開いたままになる。編集画面内の未確定入力は先に確定するかキャンセルする。元DBへの保存成功表示を確認してから終了する。別プロセスや同期ソフトとの競合を表示された場合は、新規名へ保存して内容を照合する。

保存はLinuxのローカルファイルを対象として検証している。ネットワーク・FUSE・同期先全般の耐久性は保証しない。独立した定期バックアップを保持し、同じDBを複数アプリから同時編集しない運用を基本にする。

ユーザー名・パスワードのコピーは、上流の参照式を解決した値を提供する。アプリは10秒の期限やロックで新規の提供を停止するが、GNOME・履歴ツール・貼付先が既に取得したコピーは取り戻せない。注意画面の説明を確認する。アプリが提供を止めたことを、デスクトップ全体からの完全消去とは扱わない。

## ロックと未確定の入力

アプリ内のキー・クリック等が5分間無い場合に自動ロックする。他アプリの操作や単なるマウス移動は期限を延ばさない。画面ロック・スリープ通知もロックの契機。OSのロック解除だけではDBを再解除せず、認証を必要とする。

編集画面でまだ保存していない入力は、自動ロック時に消去される。モデルに確定した編集の復旧コピーと区別する。途中の生成パスワードや未送信のマスターパスワードも同じ扱い。監視の警告が残る環境は、正常なGNOMEでの画面ロック・スリープ保護を確認した環境とは扱わず、原因を確認する。

## 復旧

通常保存の前後で作る暗号化記録は、元のファイルの隣の `.keepassxc-gnome-save-…/` に残る。作成途中・保存完了後の両方の記録を含み得る。削除後の古い秘密や過去の鍵設定も残るため、バックアップとして管理する。

1. 保存失敗・結果未確定・競合が表示されたら、再度の上書きを急がず、保存先とメニューの「復旧用ファイル」を確認する。公開後のエラーでは保存先が既に更新されている可能性がある。
2. 「復旧用ファイル」では元DBのあったフォルダーを選ぶ。対象名・時刻・状態を確認し、「コピーを開く」で認証する。
3. 内容を確認し、別の通常フォルダーへ新しい名前で保存する。元DBへの自動復元・自動マージは行わない。
4. 必要な版を確保した後に、使っていない古い記録をアプリから削除する。使用中の記録は削除できない。

確定した未保存編集の自動復旧はメニューの「未保存の変更を復旧」。既定の保存先は `~/.local/state/keepassxc-gnome/recovery/`（XDG_STATE_HOMEを指定した場合はその配下）。実機検証で使った専用profileは通常の既定値と異なる。

同一保存対象で通常保存の記録が64件に達すると、古い記録を勝手に消さず次の保存を拒否する。一覧にも上限があり、不完全な一覧の表示を無視しない。自動復旧は現在のセッションの直近2件を保つが、全過去セッション合計のディスクquotaではない。定期的に必要なバックアップを確保して整理する。journal破損等で一覧へ出ない記録の扱いは [安全保存・復旧](safe-save-recovery.md)。

暗号化ファイルの通常削除はSSD・スナップショット等からの安全消去ではない。暗号化コピーも保護対象として扱う。

## 表示・キーボード・Orca

日本語・英語は起動環境の言語から選び、それ以外は英語。明暗はGNOMEの設定へ追従する。アプリを検証コマンドから起動した場合、コマンドのLANG / LC_*がデスクトップと異なれば表示言語も変わり得る。

| キー | 操作 |
| --- | --- |
| Ctrl+O | DBを開く |
| Ctrl+S | DBを保存 |
| Ctrl+Shift+S | 新しいファイルへ保存 |
| Ctrl+F | エントリーを検索 |
| Ctrl+L | DBをロック |
| Ctrl+N | エントリーを作成 |
| Ctrl+Shift+N | DBを作成 |
| Esc | ダイアログ等を閉じる |

Orcaでは欄名を確認してから入力する。通常のDB名・タイトル・ユーザー名は文字を読み上げることがある。秘密欄では伏せ字を確認する。明示的に文字表示を有効にした状態の秘密は、画面と支援技術へ露出し得る。必要な操作後は伏せ字へ戻す。

## メモリと報告

短時間の個人利用を対象とし、検証上の目安は1回5〜30分程度。時間超過で強制終了する仕様ではない。現在のlibadwaitaにはダイアログ作成回数に応じた保持問題があり、描画キャッシュも増減する。長時間試験の増加基準は未達。保存とロックを確認してアプリを終了すると、プロセスのメモリは回収される。詳しい根拠は [保持量の調査](gui-retention-characterization.md)。

問題の報告には版、Ubuntu / GNOME、操作、表示された理由、再現に使った合成データの条件を記載する。スクリーンショット・パス・ログに個人情報や秘密が無いことを確認する。資格情報や本番DBを開発者へ送る手順は用意しない。

## Enterでの確定と選択色

DB作成・解除、グループ名、エントリーのタイトル・ユーザー名・パスワード・URLはEnterで主操作を実行できる。空欄・確認PW不一致等では実行しない。エントリーは「エントリーを保存」と同じ確定操作で、ファイルの保存は従来どおりメイン画面または終了時に行う。メモのEnterは改行。フォーカスされた補助ボタンには、そのボタンの通常操作が優先される。

選択行はアクセント20%と標準背景80%の固定混色を使い、通常の文字色・濃さで表示する。[変更・確認範囲](default-actions-selection-tint.md)。
